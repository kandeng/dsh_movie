# Phase 8 Plan: ComfyUI GPU Media Backend — Local-First Image/Video Generation via the MediaProvider Seam

- Status: 📝 PROPOSED (2026-08-09; rev 2 local-first 2026-08-09) — design only; nothing is wired yet. The `MediaProvider` seam today ships a canned placeholder + the Bailian "Happyhorse" **video** provider; **image is UNAVAILABLE** (D15). This plan adds a **ComfyUI** server as the real image/video generation backend behind that seam — **local-first: the same Ubuntu box as the DSH server, on the RTX 3070 Ti (8 GB), reached over loopback** — plus the output-media plumbing, docs, and verification. The original enterprise-H100-in-firewall placement is preserved as a deferred, config-only deployment option (D13).
- Depends on: `phase5-functional-node-palette.md` (the functional catalog, the D15 availability gate `movie-executor/model-catalog.ts`, the `MediaProvider` seam `movie-executor/media-provider.ts`, and the config-gated off-host precedent `movie-executor/video-provider.ts`), `phase6-node-card-and-editor.md` (`contentRef` D5, the read-only card media stub), `phase7-external-skills-and-asset-market.md` (the `<roomDir>/artifacts/` convention from P7-M6, the fail-closed sandbox/health discipline, and the Leg B run lifecycle in `movie-executor/runner.ts`), `doc/architecture.md` §4.2–4.3 (why we keep the ComfyUI protocol + its HTTP/WS API) and §6.3 (inference delegated to a separate operator-managed process; rev 2 places that process on the same box's GPU — the DSH *process* still runs no model code, D13).
- Scope: **server + docs + client media pipeline**. The server gains one new media provider (`comfy-provider.ts`) + workflow templates + a config gate; the D15 inventory flips `image` (and optionally a second `video` route) to available; the room notifier gains a real media-upload path (`sendFile`) and the canvas card stub resolves the generated artifact. Docs gain a thin README subsection + a full GPU-backend ops doc + an architecture section. **Explicitly NOT** in scope: replacing Leg B/Leg C with a raw ComfyUI passthrough, changing the canvas UI or the protocol graph shape, or exposing ComfyUI's native UI to end users.

## 1. Goal

Let the canvas's **image** and **video** generator nodes produce *real* media by delegating inference to a **ComfyUI server running on the local RTX 3070 Ti (8 GB) — a separate operator-managed process on the same Ubuntu box as the DSH server, reached over loopback** — without putting any Python/model code in the DSH process or repo and without changing the Toonflow canvas UX. The remote enterprise-H100 placement remains a deferred config-only option (D13).

The four founding questions this plan answers:

1. **Where does generation run?** In a separate, operator-managed **ComfyUI** process on the **local GPU (RTX 3070 Ti, 8 GB)** — same box, loopback endpoint (§6.3's "self-hosted service" — the image/video analogue of the vLLM/Ollama/SGLang text example; rev 2 collapses the physical boundary to one machine while keeping the process boundary). dsh_movie only *submits graphs over the wire*; it manages no weights and runs no model code (D7). The H100-in-firewall variant is the same architecture with a different `DSH_COMFY_BASE_URL` (D13).
2. **How does a generator node reach it?** Through the **existing `MediaProvider` seam** (Mode A). `ImageGenerator`/`VideoGenerator` already dispatch there; we add a `ComfyMediaProvider` that maps each node to a server-held ComfyUI **workflow template**, submits it (`POST /prompt`), tracks it (`/ws` or `/history`), and returns the output (D1/D3/D5).
3. **How does the media get back to the user?** Real bytes are pulled from ComfyUI (`/view`), uploaded into the room through **authenticated media** (`RoomPoster.sendFile`), written under `<roomDir>/artifacts/`, and referenced by the node's `contentRef` so the card stub plays it and downstream nodes consume it (D6). *This closes a real gap: today media artifacts are echoed as **text** only.*
4. **How do we stay safe and honest?** The endpoint is **config-gated** (mirroring `videoConfigFromEnv`), **loopback-bound** (token optional on loopback, mandatory for any non-loopback bind), accepts **only server-held templates** (never client-authored graphs), probes health before flipping a modality available, and **fails closed** to the D15 `ModelUnavailableError` + `customer_service` notice when unreachable (D2/D9/D10).

Model *routing* still honors the DSH model rule: ComfyUI is reached as a **configured media endpoint** (the sanctioned `MediaProvider` seam, same precedent as the Happyhorse video provider's `fetch`), with the base URL/token held in env — never hardcoded, never a new app-layer model client; loopback today, remote H100 later via the same env (D13).

## 2. Current state (what exists today)

- **The media seam.** `movie-executor/media-provider.ts`: `MediaProvider.generate(step, inputs) → { artifact?, media? }`; `cannedMediaProvider` (offline placeholder) and `createRoutingMediaProvider({ video?, fallback })` which routes only `VideoGenerator` to a real provider and everything else to canned (L62–69).
- **The one real off-host provider.** `movie-executor/video-provider.ts`: Bailian "Happyhorse" via DashScope async create→poll over `fetch`; **config-gated** by `videoConfigFromEnv` (`DSH_VIDEO_MODEL` + key → `undefined` when absent, so the provider is never constructed); returns `{ artifact: <url>, media: 'video' }`. This is the exact template Phase 8 mirrors.
- **The D15 availability gate.** `movie-executor/model-catalog.ts`: `ModelInventory { text, video, image, audio }` → `availabilityFromInventory()`; unlisted modalities **fail closed** to `unavailable`. An unbacked generator throws `ModelUnavailableError`; `runner.ts` (L266–285) posts `MODEL_UNAVAILABLE_NOTICE` via `customer_service` and settles the node `error` with reason `model-unavailable`, short-circuiting dependents to `skipped`.
- **The injection block.** `gateway/src/index.ts` L216–233: builds `videoConfig`/`videoProvider`, `routingMediaProvider = createRoutingMediaProvider({ video?, fallback: canned })`, and `availability = availabilityFromInventory({ text: llmText!==undefined, video: videoProvider!==undefined, image: false, audio: false })`. **Image is hard-wired `false`.**
- **The runner dispatch + lifecycle.** `movie-executor/runner.ts`: media steps call `deps.mediaProvider.generate(currentType, currentInputs)` (L244), broadcast `executed`/`executing`/`execution_success` over the Leg B WS (L248–263), and echo each artifact into the room via `deps.notifier.echoArtifact(roomId, classType, artifact, kind)`.
- **The output gap.** `movie-executor/room-notifier.ts`: `echoArtifact` (L106–109) posts media as **text** (`[classType] <artifact>`) via `RoomPoster.sendText`. **There is no `sendFile`/upload path** — so a real generated image/video is not yet delivered as playable room media. This is the largest new surface (D6).
- **The node types.** `protocol/src/nodes.ts`: `NodeModality = 'text'|'image'|'video'|'audio'`; `ImageGenerator` (modality `image`, output `image:IMAGE`, widget `image:STRING`), `VideoGenerator` (modality `video`, output `video:VIDEO`, optional `image:IMAGE` input), `MediaConcat`. `protocol/src/templates.ts` already wires `ImageGenerator`/`VideoGenerator`/`MediaConcat` into starter graphs.
- **The protocol stance.** `doc/architecture.md` §4.2–4.3: we deliberately **keep ComfyUI's protocol and backend** (`POST /prompt`, `/queue`, `/interrupt`, `/free`, `/history`, `/view`, `/object_info`, `/ws`, `/upload/image`, `/system_stats`) and only replaced its *frontend UI*. Leg B is currently a **ComfyUI-subset** served by dsh_movie's own gateway with canned execution (`fixtures.ts` stub advertises `/object_info` + `/system_stats`).

## 3. Decisions D1–D13

### D1 — Integration mode: ComfyUI behind the `MediaProvider` seam (Mode A), not a Leg B replacement
The functional generator nodes dispatch through `MediaProvider`; we add a `ComfyMediaProvider` there. We do **not** point Leg B at the real ComfyUI server wholesale: dsh_movie's graph uses **functional class types** (`ImageGenerator`, `VideoGenerator`, `MediaConcat`, `FamilyDispatch`, `VideoCompositor`) plus Leg C governance (family dispatch, availability gate, ops/narration), not ComfyUI's `KSampler`/`VAE`/latent nodes. A raw passthrough would bypass that governance. Mode A keeps the canvas, protocol, and Leg C untouched; ComfyUI is purely a per-generator execution backend.

### D2 — Config-gated endpoint, loopback-first (mirror `videoConfigFromEnv`)
A new `comfyConfigFromEnv(env)` returns `undefined` unless a base URL is present, so the provider is never constructed when unconfigured and the D15 gate keeps image/video `unavailable` (fail closed). Env: `DSH_COMFY_BASE_URL` (local-first: `http://127.0.0.1:8188`; a remote H100 URL is the deferred D13 switch), `DSH_COMFY_TOKEN` (optional bearer on loopback, **required for any non-loopback bind**, never logged), `DSH_COMFY_POLL_MS` (default 1500), `DSH_COMFY_TIMEOUT_MS` (default 900000 — local 8 GB video renders run minutes), `DSH_COMFY_INFLIGHT_MAX` (default 1, see D8). **Reconciliation with the "no direct model HTTP" rule:** that rule targets hand-rolled Bailian/DashScope clients + key sprawl; ComfyUI is an *internal workflow engine* reached as a **configured media endpoint** — the exact precedent `video-provider.ts` already sets (a provider doing `fetch` to an env-configured URL, loopback today). Keys live in env/DSH settings; the DSH process stays model-code-free — the GPU belongs to the separate ComfyUI process (D13). Recorded here as an explicit decision.

### D3 — One server-held workflow template per generator modality; `class_type` → template map
ComfyUI consumes a **graph JSON**. dsh_movie holds a small set of versioned **workflow templates** server-side (not client-authored), **sized for the local 8 GB card (R6)**: `image` (SD1.5 fp16, or SDXL fp16 + `--medvram`/fp8-stored weights; optional img2img when an `image` input is present; Flux-dev GGUF Q4 only as an optional slow experiment) and `video` (LTX-Video 2B distilled, or Wan2.1 T2V-1.3B at 480p ~5 s clips with the umt5-xxl text encoder fp8-stored; 14B Wan / HunyuanVideo / full Flux do **not** fit 8 GB). Templates bake resolution/duration caps for the 8 GB envelope. A template is a ComfyUI prompt graph with named injection points; `ComfyMediaProvider.generate(classType, inputs)` maps the node's resolved inputs (`prompt`/`resolved` → positive prompt, `image` → an `/upload/image`-provided input, seed/size/duration → template params) onto the template, then submits. Templates validate against `/object_info` at activation (D9) so a missing custom node (e.g. a GGUF loader) degrades instead of failing mid-run.

### D4 — Availability flip via the D15 inventory (settings-gated, per-run re-check)
`index.ts` L228–233 changes `image: false` → `image: comfyImageReady`, and (optionally) routes `VideoGenerator` to ComfyUI instead of/alongside Happyhorse. `comfyImageReady` = a ComfyUI config is present **and** the `image` template validated against `/object_info`. Adding the endpoint in env flips image to available **with no code change**; the gate re-checks per run.

### D5 — Async execution + progress mapping onto the existing Leg B lifecycle
`POST /prompt` → `{ prompt_id }`; track via `/ws` (`executing`/`progress`/`executed`) with a `/history/{prompt_id}` poll fallback. Map ComfyUI progress onto the runner's existing `deps.broadcast([...])` Leg B channel so the canvas shows **real per-node progress** for free. Honor `DSH_COMFY_TIMEOUT_MS`; on cancel/timeout issue `POST /interrupt`. Failures throw (→ node `error`), never silently can.

### D6 — Output media pipeline: bytes → authenticated media → `contentRef` → card stub (closes the text-only gap)
On success, read the output file(s) from ComfyUI (`/history` outputs → `GET /view`), then: (a) upload into the room via a **new `RoomNotifier.sendFile`/media-echo path** (`RoomPoster.sendFile`) so it appears as real playable media; (b) persist under `<roomDir>/artifacts/` (mirroring P7-M6); (c) set the node's `contentRef` with `origin: 'generated'` so the read-only card stub (phase6 D1/D5) resolves and plays it, and downstream `MediaConcat`/`VideoCompositor` consume the artifact — not a bare cross-origin ComfyUI URL. **The browser never talks to ComfyUI directly** (D10/R8): the gateway proxies bytes and re-publishes through authenticated media.

### D7 — Installing/running models is ComfyUI's job, not dsh_movie's
Model install/run happens **on this box, outside the repo**: a dedicated venv + torch cu12x (Ampere sm_86), a pinned ComfyUI tag, optional ComfyUI-GGUF custom node, checkpoints under `ComfyUI/models/` on local storage — operator-managed (we are the operator, D13). dsh_movie manages **no** weights and ships **no** Python. The repo documents the dsh_movie-side contract (env + smoke test) plus a local install/run guide (D11) and links out to upstream ComfyUI. The install itself is an owned milestone (**P8-M1**), not an implicit precondition of the live smoke.

### D8 — Concurrency & queueing
ComfyUI is **single-queue by default**. Strategy: a per-provider in-flight cap (`DSH_COMFY_INFLIGHT_MAX`); the Leg B executor already schedules prompts as async `movie-exec` jobs, so backpressure simply keeps a run queued. The local fleet is **one GPU**, so pooling is **deferred (optional/later, D13)**: for multiple GPUs/H100s, run one ComfyUI per GPU behind a small router/pool (config lists endpoints; round-robin/least-busy); P8-M5 verifies pooling against the mock only. Autoscaling the pool is out of scope.

### D9 — Health/readiness probe + honest degradation
At gateway activation, probe `GET /system_stats` + `GET /object_info`; a modality flips available **only** when reachable and its template's required node types are present. If ComfyUI is down/unreachable at run time, the gate fails the node → `ModelUnavailableError` → `customer_service` posts the D15 notice → dependents `skipped` (never a canned placeholder). Optionally serve a cached last-good readiness between probes.

### D10 — Security: loopback-bound, token when non-loopback, server-held templates only
ComfyUI is effectively arbitrary-code-execution on its box, so: bind it **loopback-only** (ComfyUI's default; never pass `--listen` beyond 127.0.0.1); `DSH_COMFY_TOKEN` is optional on loopback (single-user dev box) but **mandatory for any non-loopback bind**; accept **only server-held templates** (D3) — **never** a client-authored graph — so the canvas can't become an RCE vector (a product invariant for the later multi-tenant ECS story, not just a firewall mitigation); enforce a **node-type allow-list** in templates; and proxy all output through the gateway (D6). The canvas remains the only user-facing surface (Toonflow UI, not ComfyUI's).

### D11 — Docs placement (ops guide born at P8-M1; the rest AFTER implementation)
- **README.md**: a thin **§3.5 "GPU media backend (ComfyUI, optional)"** — what it enables, the `DSH_COMFY_*` env (loopback default), how to smoke-test **on this box**, and links to the local ops guide + upstream ComfyUI docs.
- **doc/comfyui-gpu-backend.md** (new): the **local RTX 3070 Ti ops guide** — venv + torch cu12x (Ampere), pinned ComfyUI tag, the 8 GB model list with sizes/hashes, `--medvram`/tiled-VAE/offload notes, template authoring, troubleshooting; a short **deferred remote-H100 appendix** (D13) records the config-only switch.
- **doc/architecture.md**: a new **§10 "GPU media backend (ComfyUI)"** — the seam, the template map, the output-media flow, the security stance (+ a mermaid overview).
Rationale: the README documents only **shipped, wired** dependencies (PostgreSQL, Synapse); a ComfyUI section is added once the integration is real, and heavy ops live in `doc/`. Sequencing: `doc/comfyui-gpu-backend.md` is **created at P8-M1** (install commands recorded as executed) and completed at P8-M6; README §3.5 and architecture §10 land only after the wiring is real.

### D12 — i18n
Any new user-facing strings (e.g. a ComfyUI-specific progress label or a "image backend unreachable" nuance beyond the generic D15 notice) are added as Chinese-keyed entries × 21 catalogs at pinyin-sorted positions, per the established i18n workflow. Reuse the existing `MODEL_UNAVAILABLE_NOTICE` where possible to minimize new keys.

### D13 — Local-first deployment profile; remote H100 deferred as a config-only switch (rev 2)
Everything runs on the one Ubuntu box: DSH server, Synapse, Vite client, and ComfyUI on the RTX 3070 Ti (8 GB GDDR6X, Ampere sm_86). The seam is **location-agnostic** — moving to the enterprise H100/ECS later is an env change (`DSH_COMFY_BASE_URL` + token) plus a template/model-set swap, **no code change**. The D4 inventory lists the local-capable model ids. The architecture's "CPU-only host" claim is reworded to "the DSH *process* runs no model code": the machine has a GPU, but it belongs to the separate ComfyUI process. VRAM sizing, timeouts, and the loopback/token posture above (D2/D3/D7/D8/D10, R6/R10) all follow from this profile.

## 8. Risks

- **R1 — Security: ComfyUI ≈ arbitrary code exec on its box.** Mitigated by D10: loopback-only bind (token when non-loopback), **server-held templates only** (no client graphs), a node-type allow-list, and gateway-proxied output (browser never reaches ComfyUI).
- **R2 — Tension with the "model calls ride DSH, no direct model HTTP" decision.** Mitigated by D2: ComfyUI is a *configured media endpoint* on the sanctioned `MediaProvider` seam (the `video-provider.ts` precedent), env-held URL/token, the DSH process stays model-code-free (D13). Explicitly recorded and signed off at P8-M0.
- **R3 — Output-media plumbing is the largest new surface** (`echoArtifact` is text-only today; no `sendFile`). Mitigated by isolating it in P8-M2 with a dedicated verify assertion (room media event + artifact file + resolvable `contentRef`).
- **R4 — Long video renders vs job/WS timeouts.** Mitigated by the existing async `movie-exec` job model, a generous configurable `DSH_COMFY_TIMEOUT_MS` (default 900 s — local 8 GB video renders run minutes; raised from Happyhorse's 300 s precedent), and `/ws` progress heartbeats keeping the Leg B channel alive.
- **R5 — ComfyUI single-queue throughput.** Mitigated by D8: in-flight cap + queue backpressure; one instance per GPU behind a router for parallelism.
- **R6 — 8 GB VRAM OOM on the RTX 3070 Ti.** H100-class models (14B Wan, HunyuanVideo, full Flux) do not fit; mitigated by the 8 GB-capable template/model list (D3/D7: SD1.5/SDXL, LTX-Video/Wan2.1-1.3B 480p), fp8 weight *storage*/GGUF, `--medvram` + smart offload to system RAM, tiled VAE, and resolution/duration caps baked into templates; the `/object_info` probe still fails closed on missing node types.
- **R7 — ComfyUI API / template version drift.** Mitigated by pinning the ComfyUI version, validating templates against `/object_info` at activation, and degrading to `unavailable` on mismatch rather than failing mid-run.
- **R8 — Cross-origin / unauthenticated `/view`.** ComfyUI's `/view` is unauthenticated; mitigated by the gateway downloading bytes and re-publishing through authenticated media (D6) — the raw URL is never surfaced to the browser.
- **R9 — Legacy canned/verifier regressions.** Routing falls back to canned when ComfyUI is unconfigured (exactly like the video route), so offline verification and the six-step legacy pipeline stay unchanged.
- **R10 — Ampere (sm_86) has no FP8 tensor cores; same-box RAM headroom.** fp8 is weight-storage-only (upcast compute) — promise fp16/bf16 throughput, never H100-class fp8 speeds; ComfyUI's offload leans on system RAM (≥32 GB recommended, checked in the ops doc). Sustained video renders keep the desktop card at full load — verify cooling; DSH/Synapse/Vite contend for CPU/RAM only, never VRAM.
